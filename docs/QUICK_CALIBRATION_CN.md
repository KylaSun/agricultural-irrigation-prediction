# 四探头快速校准程序

## 文件

在 Arduino IDE 中打开：

```text
firmware/esp32_soil_calibration/esp32_soil_calibration.ino
```

这是独立校准固件，会输出人类可读提示，不能同时作为 Python collector 的 JSONL 数据源。完成校准后，需要重新上传正式固件 `firmware/esp32_irrigation_demo/esp32_irrigation_demo.ino`。

## 使用步骤

1. 核对 GPIO32、33、34、26，以及四支探头的 3V3 和公共 GND。`soil_04` 当前改用 GPIO26（经典 ESP32 的 ADC2），校准程序不启用 Wi-Fi；如果未来在 ESP32 端启用 Wi-Fi，需要重新评估这一路 ADC 接线。
2. 上传校准程序。
3. 打开 Arduino Serial Monitor，将波特率设为 `115200`；行尾选项任意。
4. 输入 `m`，观察四支探头的实时原始值；再次输入 `m` 停止。
5. 把四支探头放入约定的干燥土壤，保持未来使用时相同的插入深度和方向，等待稳定。
6. 输入 `d`。程序对每支探头采集 30 个平均读数，并取中位数作为干端。
7. 把四支探头放入约定的湿润、排去多余水分的同类土壤，等待稳定。
8. 输入 `w`，记录湿端。
9. 输入 `p`，复制输出的 `DRY_RAW` 和 `WET_RAW` 两行。
10. 将两行替换到正式固件中，再重新上传正式固件。

当前仓库已经写入 2026-10-18 的一次实测结果：

```cpp
static const int DRY_RAW[PROBE_COUNT] = {1907, 959, 408, 740};
static const int WET_RAW[PROBE_COUNT] = {0, 0, 0, 0};
```

其中湿端是 DFRobot 官方方法中的水端。四路水端为 0 与该方法一致，但干端差异较大，因此这组值仅作为暂定实验校准。太阳能供电、固定土壤、插入深度和接线全部确定后，应完整重复至少一次干端/湿端测量；复测完成前不要把这些百分比解释为真实体积含水率。

## 串口命令

| 命令 | 作用 |
|---|---|
| `s` | 读取一次四探头原始值 |
| `m` | 开启/关闭每秒原始值监视 |
| `d` | 采集四探头干端 |
| `w` | 采集四探头湿端 |
| `p` | 打印可复制的数组和干湿端差值 |
| `r` | 清除本次上电保存在 RAM 中的结果 |
| `h` | 重新显示帮助 |

## 如何判断结果是否需要重测

- `span` 表示一次端点采集过程中最大值和最小值之差。某支探头的 span 明显大于其他探头时，先检查探头是否移动、接线是否松动、供电是否稳定。
- `gap` 是同一探头干端和湿端的绝对差。程序只报告数值，不自行设定合格阈值；应结合重复测量和到货探头表现判断。
- 建议完整重复一次干端和湿端测量。如果两次结果差异较大，不要直接取其中一次，应先检查实验条件。
- 四支探头必须分别保留校准值，不要把一支探头的结果复制给其他探头。

## 边界

- 程序只把结果保存在 RAM，ESP32 重启后结果消失，因此要及时复制。
- 得到的是两点校准后的相对湿度，不是真实体积含水率。
- 正式实验应记录土壤类型、插入深度、干湿状态定义、日期、供电方式和校准人员。
- 不要将接头、ESP32 或裸露导线浸水。
- 校准、烧录和电脑采集统一使用电脑 USB 给 ESP32 供电，并断开太阳能管理模块到 ESP32 的 5 V 输出，避免双电源倒灌。
